1. HIGH-LEVEL ARCHITECTURAL OVERVIEW
========================================================================================

SnackBot Cloud is built upon a Domain-Driven Modular Single-Page Architecture (SPA):

  +-----------------------+      +-----------------------+      +-----------------------+
  |    CUSTOMER CLIENT    |      |  MERCHANT / CASHIER   |      |    PLATFORM ADMIN     |
  |  (Mobile QR Scanner)  |      |   (Desktop / Tablet)  |      |   (Superuser Portal)  |
  +-----------+-----------+      +-----------+-----------+      +-----------+-----------+
              |                              |                              |
              +----------------------+       |       +----------------------+
                                     |       |       |
                                     v       v       v
                            +---------------------------------+
                            |       Vite + React 18 SPA       |
                            |   (Tailwind CSS + Lucide Icons) |
                            +----------------+----------------+
                                             |
                                             v
                            +---------------------------------+
                            |  Global State & Route Dispatch  |
                            |    (App.tsx / Context Providers)|
                            +----------------+----------------+
                                             |
                                             v
                            +---------------------------------+
                            |  Domain Feature Modules (src/)  |
                            |  (auth, reports, ordering, etc) |
                            +----------------+----------------+
                                             |
                                             v
                            +---------------------------------+
                            |      Supabase Client SDK        |
                            |     (REST, Auth, Realtime)      |
                            +----------------+----------------+
                                             |
                                             v
                            +---------------------------------+
                            |   Supabase Cloud / PostgreSQL   |
                            |   (RLS Policies, Tables, Auth)  |
                            +---------------------------------+

3.4. SUPABASE KEEPALIVE & AUTOMATED HEARTBEAT FLOW
----------------------------------------------------------------------------------------
Objective: Prevent Supabase Free Tier projects from automatically sleeping after
           7 days of inactivity.

 Two Autonomous Heartbeat Vectors:
 ---------------------------------

 VECTOR A: In-Browser Hook (`useSupabaseKeepalive`)
 -------------------------------------------------
  Active Staff / Customer loads SnackBot
            |
            v
  Checks `_keepalive.last_ping` timestamp
            |
    Has it been >= 6 days since last ping?
            |
            +--- NO  ---> Do nothing (prevents unnecessary database writes)
            |
            `--- YES ---> Execute UPSERT on `_keepalive`:
                          - id = 1
                          - last_ping = NOW()
                          - ping_count = ping_count + 1

 VECTOR B: GitHub Actions Automation (`.github/workflows/supabase-keepalive.yml`)
 --------------------------------------------------------------------------------
  Trigger: Scheduled Cron (`0 0 */5 * *` - Every 5 days at 00:00 UTC)
            |
            v
  GitHub Runner spins up Ubuntu container
            |
            v
  Executes `node scripts/keepalive.js`
            |
            v
  Connects to Supabase REST API via Project Anon Key
            |
            v
  Executes UPSERT on `_keepalive` (Increment counter + Timestamp update)
            |
            v
  Supabase registers active API + Database transaction
  (Project pause timer is reset to zero)

  +-----------------------+              +-----------------------+
  |       merchants       | 1          * |       branches        |

              | 1                                    | 1

              | *                                    | *
  +-----------------------+              +-----------------------+
  |         users         |              |        tables         |
  |-----------------------|              |-----------------------|
  | id (PK / auth.users)  |              | id (PK)               |
  | merchant_id (FK)      |              | branch_id (FK)        |
  | branch_id (FK)        |              | table_number          |
  | role, pin_code, email |              | qr_code_id (Unique)   |
  +-----------------------+              +-----------------------+
                                                     | 1
                                                     |
                                                     | *
  +-----------------------+              +-----------------------+
  |      menu_items       | 1          * |        orders         |
  |-----------------------| ------------ |-----------------------|
  | id (PK)               |              | id (PK)               |
  | branch_id (FK)        |              | branch_id (FK)        |

  +-----------------------+              +-----------------------+
              | 1                                    | 1
              |                                      |
              | *                                    | *

  |    order_items        |              |       payments        |

  +-------------------------------------------------------------+
